# 都市更新選屋資訊查詢系統 — 設計規格

日期：2026-08-17
狀態：已確認

## 1. 目標與概述

提供一個公開、唯讀的網頁應用，讓地主與服務人員在手機/平板瀏覽都市更新案的房屋與車位資訊，並即時查詢目前的選取狀態（每戶/每車位被幾位地主選中）。資料來源為單一 Google 試算表，透過 Apps Script 提供 API，前端為 React + Vite，介面風格近似 AppSheet。

## 2. 核心需求

- 資料來源：Google Sheets（單一試算表，多個工作表）。
- 資料取得：Apps Script Web App（公開、不需登入）以 JSON API 提供。
- 前端：React + Vite，手機/平板優先（響應式、觸控友善、大字卡片）。
- 存取：公開（任何人拿到連結即可瀏覽），地主不需 Google 帳號。
- 唯讀：地主只能查詢，不寫入任何資料。
- 選取狀態：顯示每戶/每車位被幾位地主選中；1 人＝藍色、2 人以上＝紅色、0＝預設色；無人數上限。
- 資料可變動：頁面載入時抓取一次，透過「刷新」按鈕或下拉重新抓取最新資料（手動刷新，非自動輪詢）。
- 部署：GitHub Pages，儲存庫 github.com/kuanbill/urho。

## 3. 整體架構與資料流

```
Google Sheets (3 工作表) → Apps Script Web App (doGet JSON API) → React 前端 (GitHub Pages)
```

1. 地主開啟 GitHub Pages 網頁。
2. 頁面載入時呼叫 Apps Script Web App，取得全部資料（JSON）。
3. 前端在瀏覽器端做過濾、排序、搜尋、選取人數彙整與平面圖格線呈現。
4. 地主點「刷新」或下拉 → 重新呼叫 API 取得最新資料。

Apps Script 部署為「任何人都可存取」的 Web App，`doGet` 依參數回傳 JSON。以 `clasp` 上傳部署。

## 4. 資料結構

僅需讀取 3 張工作表（「房屋選配位置」「車位選配位置」兩張位置表不需讀取，格線直接由價值表生成）。

### 4.1 各樓層房屋價值表
欄位：排序、單元編號、樓層、戶別、用途、產權面積/坪、每坪單價/元、該戶總價/元
用途：房屋清單、房屋詳細資料、房屋平面圖格線。

### 4.2 車位價值表
欄位：車位編號、樓層、車位單價/元、車位屬性、車位大小、規格/公分
用途：車位清單、車位詳細資料、車位平面圖格線。

### 4.3 選配基本資料
欄位：姓名、編號、應分配、共同負擔可分配、權值比、是否出資、出資10%、房屋選配、房屋選配_單價、車位選配、車位選配_單價、選配總額、部份出資額、超額選
用途：統計選屋/選車位人數。

### 4.4 彙整規則
- 房屋選屋數 ＝ 「選配基本資料」中 `房屋選配` 等於該戶別的列數。
- 車位選車位數 ＝ 「選配基本資料」中 `車位選配` 等於該車位的列數。
- 顯示顏色：1 人＝藍、2 人以上＝紅、0＝預設色。

## 5. UI 畫面與互動

整體：AppSheet 風格、手機/平板優先、頂部選單（漢堡/抽屜）、大觸控按鈕、卡片式、下拉刷新、標籤頁切換。

1. **房屋清單**：卡片/表格列出房屋，可依樓層、價格、坪數、用途等過濾排序；每張卡片顯示戶別、樓層、價值與選取人數徽章（藍 1／紅 2+）。
2. **房屋詳細資料**：點卡片進入，顯示完整欄位與目前選取狀態。
3. **車位清單與詳情**：同房屋，顯示車位編號、價值、位置與選取人數。
4. **位置平面圖**（核心）：
   - 房屋：格線，X＝樓層（1F 往上）、Y＝戶別（自由字串，如 A1/A2/A3），格內顯示「戶別 + 選屋數」並著色。
   - 車位：格線，X＝樓層（B1/B2/B3）、Y＝車位編號，格內顯示「車位編號 + 選車位數」並著色。
5. **全域搜尋**：輸入「5F-A1」「B1-16」或關鍵字，即時篩選並跳轉詳情。
6. **選取狀態總覽**：各戶/各車位被選人數，1＝藍、2+＝紅。
7. **手動刷新**：頂部刷新按鈕 + 下拉刷新。

## 6. Apps Script 端設計

- `doGet(e)` 依 `e.parameter.type` 分派回傳 JSON：`houses`、`parking`、`selections`、`all`。
- 讀取工作表第一列（標題列）動態對應欄位，轉成物件陣列（資料驅動）。
- 以 `ContentService` 回傳 JSON。
- 部署為「任何人都可存取」的 Web App。
- 用 `clasp` 上傳部署。
- 選取人數彙整在前端進行（方案 A：全量載入、前端處理）。

## 7. 前端技術

- React + Vite
- 手機/平板優先響應式設計
- 部署至 GitHub Pages（需設定 base path 與部署 workflow）

## 9. 風險與待驗證項目

- **前端 CORS**：Apps Script Web App 跨域讀取可能被瀏覽器阻擋，實作時需驗證；受阻則改用備案（HTML Service 或代理）。
- **工作表欄位**：以實際標題列動態對應，欄位增減需相容；正式上線前需以實際試算表驗證。
- **選配基本資料識別**：`房屋選配`/`車位選配` 的實際值格式需與價值表的 `戶別`/`車位編號` 一致，才能正確統計。

## 10. 非目標（YAGNI）

- 不做任何寫入/選配操作（唯讀）。
- 不做使用者登入與權限控管（公開）。
- 不自動輪詢即時更新（採手動刷新）。
- 不實作「房屋選配位置」「車位選配位置」兩張表。
